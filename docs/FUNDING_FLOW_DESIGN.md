# 資金フローを中心にした設計と運用

## 利用者の入口

企業・団体、政策事業、資料で確認できる資金経路から検索する。企業から関係事業を開くと支出先一覧に移動し、選択企業を強調できる。レビューシートの事業IDによる対応と、他資料の事業名一致候補を区別する。既存の資料別URLは維持する。

## 保存する層

1. sourceRecords: 取得済みデータの各原行をそのまま保存。資料固有の項目を落とさず、出典、掲載箇所、原文の金額、法人番号を残す。
2. observations: 原行から抽出した掲載事実。元のIDと1対1対応し、法人番号による主体、事業シート、金額の意味、年度の種類を明示する。
3. facts: 照合後の事実。初期状態では掲載行ごとに別事実とし、同名・同額のみで統合しない。
4. cases / decisions: 根拠に基づき同一案件の変更履歴を関連付ける。同一事実の再掲、変更、別案件の判断を分ける。台帳は data/funding/match-decisions.json。
5. program.graph: 資金経路。レビューの支出ブロック間の関係として保持し、個社間の送金・配分には展開しない。

法人番号なしの行は独立した記載主体。法人に「中間事業者」等の固定属性を付けず、事業内の掲載位置を保持する。共同受注額は個社への配分額にしない。所管法人の全掲載額が経産省財源とは主張しない。

## 金額と年度

GビズINFO調達掲載額、補助金掲載額、レビュー支出先掲載額、原典が明示する契約金額・交付決定額を別分類とする。契約予定総額等は未分類を維持する。0円・負数・空欄は別値。個別の支払年度は資料年度から推定しない。レビューシート年度、事業全体の予算年度・執行年度、GビズINFOの日付年度、機関公表資料の年度を分ける。

事業全体の予算・執行額は原典の集計値として別枠表示。支出先額やブロック間の金額を足して事業総額を作らない。差額を未執行・残高としない。aggregateFacts は主体・金額段階・支払年度・集計適格性が確定しない限り金額を返さない。現データには適格性を自動付与しない。

## 照合の更新方法

判断は id / type / evidence（id と fingerprint）/ reason / reviewedBy / reviewedAt / references（HTTPS URL と locator）を必須とする。fingerprint は生成された ledger ファイルに収録。

- same_fact: 互換な同一掲載事実の再掲。根拠を残し事実を1件に関連付ける。金額、段階、主体、ブロック、事業シート、年度が異なる統合は拒否。
- revision: evidence 配列の1件目が変更前、2件目が変更後。事実を両方保存し、案件内で現行版を識別。循環・分岐した後継指定は拒否。
- different_case: 同一事実・同一案件への統合と矛盾する判断を拒否。

資料変更で fingerprint が変わるとビルドを失敗させ、古い判断を無断再利用しない。同一案件と裏付けられない大量の候補を、試験用の判断で本番確定してはならない。初回移行の照合台帳は空。

## 経路の根拠と限界

既存キャッシュは directUpstreamBlocks を利用してブロック間の関係を復元する。単一路・深さ1が明示された場合だけ担当組織からの入口を復元する。legacy 経路は確定グラフに使わない。親支出先IDの集合は上流ブロックの構成行であって個社間の送金関係ではない。

次回レビュー取得から flows CSV の辺・元行番号も事業レコードに保存する。これにより支出先の掲載行がないブロックも維持する。既存分は検証済みキャッシュ由来と明示し、未取得の元行番号は捏造しない。元ZIPのURL・SHA256は receipts に保持。

同じ事業名・番号の年度間継続、親事業・内数事業は、対応資料を確認するまで確定統合しない。年度別シートを維持し、名称一致だけの他資料は候補として表示する。

## 追跡できる範囲

事業ごとに支出先掲載行、金額記載行、経路記載行、構造上除外された原資料行を表示。末端は「この資料の経路はここまで」とし最終受益者と呼ばない。未調査・非公表・未収録を区別できる根拠がない箇所は「未判定」。網羅率を捏造しない。

## 再生成・検証・公開

npm run test:pages で元データ照合、全回帰テスト、成果物のハッシュ・件数・参照整合性を検証する。各公開ビルドで explorer を再生成し、将来のGビズINFO・レビュー更新も同じ構造に入る。data/funding/** の変更も公開対象に含める。週次の主系列更新と既存の公式補足更新設定を維持し、新規の外部収集処理は追加しない。

GitHub Pagesが公開先。Sitesへの別公開は行わない。

## 既存の公開停止原因の修正

中小機構専用の全履歴JSONはmainに一度も保存されておらず、公開索引もそのファイルを使用していなかった。既存公開対象は4月の14行と2017～2019年度の検証済み577行。全履歴取得を試行したが契約相手方と法人番号の対応を確定できず停止し、候補データは公開していない。

公開ゲートは実際に掲載する591行の保存・金額・法人番号・原典URLと限定的な収録範囲を検証する。全履歴の158以上のPDF・行数会計の厳格な検証は削除せず tests/smrj-history-artifact.test.mjs に移し、全履歴取得後の公式更新workflowで必須実行する。未取得の全履歴を収録済みと扱わない。

法人番号欄の同一数字13桁（9999999999999など）は主体を統合するキーから除外する。原記載はsourceRecordsに保持する。
