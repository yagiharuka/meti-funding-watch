# GビズINFO 補助金REST API監査（2026-08-17）

## 結論

認証済みの現行REST API v2を、全件CSVで証明日が空欄となっている5法人に対して実行した。5法人すべてHTTP 200で取得できたが、対象とした問題レコードの `date_of_approval` はAPIでも `null` だった。REST APIは、全件CSVの証明日欠落を補完する別データ源ではない。

v2で `metadata_flg=true` を指定すると、補助金明細ごとに次の6項目が返る。

- キー情報 (`key_field`)
- データ品質 (`data_quality`)
- 出典元 (`source`)
- データ取込頻度 (`import_frequency`)
- 最終取得日 (`last_acquisition_date`)
- 最終更新日 (`last_update_date`)

これらは現在取得している全件CSVに既に存在する列と対応し、サンプルではキー情報もCSVの「キー情報」と一致した。したがって、全法人をREST APIで再照会しても、少なくとも今回確認した日付欠落や手続段階の識別は改善しない。

ただし、GビズINFOの法人詳細画面には、補助金明細ごとに「交付決定」「確定」「－」などを表示するステータス欄がある。この画面項目は全件CSV、法人情報JSON、REST API v2のいずれの公開スキーマにも含まれず、REST API監査だけを根拠に「GビズINFOにステータスがない」と解釈してはならない。当サイトは機械取得できない値を推測せず、各補助金行を「ステータス未取得」と表示して法人詳細画面へリンクする。

## 実データで確認できたこと

### 証明日空欄はAPIでも空欄

次の一致レコードを含め、検査対象として抽出した問題レコードの `date_of_approval` はv2でも `null` だった。

| 法人 | 名称 | 金額 | API認定日 |
|---|---|---:|---|
| 高山熔接有限会社 | ［第十二回］事業再構築補助金＿成長分野進出枠、コロナ回復加速枠（交付申請等） | 0円 | null |
| 株式会社内山製作所 | ［第十回］事業再構築補助金＿サプライチェーン強靱化枠（交付申請等） | 500,000,000円 | null |
| 全国中小企業団体中央会 | ものづくり・商業・サービス高度連携促進事業 | 4,995,691,000円 | null |
| 株式会社博報堂 | 令和5年度補正中堅・中小企業の賃上げに向けた省力化等の大規模成長投資補助金 | 298,606,326,340円 | null |

### 「交付申請等」は金額段階を確定しない

名称に「交付申請等」を含むサンプルで、0円の行と5億円の行がともに確認された。よって「交付申請等」と0円の対応は中小企業庁の0円61件では完全だが、逆方向の「交付申請等なら0円」や「0円だから交付決定前」は成立しない。

### v2には手続段階を区別する項目がない（法人詳細画面には表示あり）

現行Swaggerの補助金明細スキーマは、`date_of_approval`（説明は「認定日」）、`title`、`amount`、`target`、`government_departments`、任意の `meta-data` である。採択日と交付決定日を別々に返す項目、状況名称、交付決定・変更・確定・支払を識別する項目はない。

したがって、REST APIまたは全件CSVだけからGビズINFO掲載額を交付決定額、確定額、実支払額のいずれかへ自動分類しない。法人詳細画面で確認できるステータスと混同せず、名称に手続段階らしい語が含まれる場合も、原文表示と検索補助に限る。

## v1とv2の差

旧v1レスポンスには `joint_signatures`、`note`、`subsidy_resource` がスキーマ上存在するが、今回の問題サンプルではいずれも有効な補完値を確認できなかった。公式のv1→v2変更点一覧では、補助金情報から「連名リスト」「備考」「補助金財源」を削除したと明記されている。
